## Харнесс-кит: правила окна (версия 1.0.0, 2026-10-28)

Источник правил: Anthropic «Effective harnesses for long-running agents» (11.2025), «Harness design for long-running apps» (03.2026), репозиторий anthropics/cwc-long-running-agents, гайд по Opus 5.5 (unattended runs); разбор применимости в `.claude/harness-kit/README.md`. Правила короткие и исполняются файлами: хуками, субагентом и шаблонами, не только текстом.

1. **Контракт до работы.** В стартовом промпте активности пять строк: Результат / Не делаем / Готово когда / Останавливаюсь если / Кто принимает, плюс строка «Бюджет». Контракта нет: написать черновик по `.claude/harness-kit/templates/СТАРТ-шаблон.md`, согласовать с владельцем до первого тяжёлого действия. Новая активность заводится командой `/старт-активности`.
2. **Проверка перед «готово».** Слово «готово» и создание PR разрешены после вердикта `PASS` субагента `оценщик` (свежий контекст, только чтение и git, инструменты записи отключены) и после открытия конечного артефакта глазами читателя. Процедура: `/готово`. Для документов, которые дальше правит человек, достаточно открытого артефакта и вердикта по контракту.
3. **Конец хода.** Ход, закончившийся текстом при открытых пунктах контракта, когда ничто не требует решения владельца, завершением не считается: следующее действие делается в этом же ходе. Отчёт о прогрессе кладётся в то же сообщение, что и следующее действие.
4. **Критерии версионируются.** Формулировки пунктов «Готово когда» и пунктов state-файлов (STATE.json, features.json) после согласования не редактируются: изменение означает новую версию с датой и причиной, старая остаётся в истории. В state-файлах меняются только `status` и `evidence`; хук verify-gate не даёт записать в них без прочитанного доказательства.
5. **Бюджет.** Соло сначала; многоагентный прогон, когда соло не справился или цена ошибки высока. У прогона есть потолок (токены или минуты, число агентов), записанный в стартовом промпте; после 20:00 прогоны дольше 20 минут только после вопроса владельцу про квоту. После прогона строка в HANDOFF «Прогоны»: дата, runId, модель и effort, токены, минуты, результат, команда возобновления. Шаблон прогона с учётом бюджета: `.claude/harness-kit/templates/workflow-шаблон.js`.
6. **Судьи калибруются.** Многосудейная фаза заканчивается критиком, который разбирает расхождения судей и устаревшие источники; подсчёт голосов без разбора не считается результатом. Судья проверяет факты по git и файлам, не по фокусу и не по HANDOFF, и записывает дату источника.
7. **Хэндофф перезаписывается.** Верх HANDOFF: четыре блока (Сейчас / Сделано, не повторять / Дальше / Решения владельца, не пересматривать), история в `HANDOFF-история.md`. Второй заголовок «читать первым» в одном файле это сигнал свернуть; SessionStart-хук показывает такие стопки на каждом старте. Шаблон: `.claude/harness-kit/templates/HANDOFF-шаблон.md`.
8. **Влитие кодом.** Хук merge-guard переводит `gh pr merge`, `git merge <ветка>`, push в main и force-push в режим «спросить владельца». Это Протокол влития, закреплённый технически; подтягивание main в рабочую ветку (`git merge main`) не трогает.
9. **Ревизия харнеса.** При смене модели и раз в квартал: `/харнесс-ревизия` ищет правила без следа применения, противоречия и устаревшие указатели и предлагает список на удаление. Носители правил не растут без ревизии.

Хуки: `.claude/hooks/harness/` (SessionStart, Stop только печатает незакоммиченное, PreToolUse Bash, PreToolUse Write|Edit, PostToolUse Read|Bash). Codex исполняет только SessionStart-хук; правила 2, 4, 8 для Codex-сессий держатся на тексте AGENTS.md.
