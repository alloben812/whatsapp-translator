## Харнесс-кит: правила окна (версия 1.1.0)

Правила кита дополняют правила этого репозитория и уступают им при расхождении: носитель хэндоффа (HANDOFF.md, SESSION.md, STATUS.md), схема веток, порядок влития и деплоя берутся из местного CLAUDE.md. Кит добавляет только девять правил ниже и ничего из местного порядка не отменяет. Источник: Anthropic «Effective harnesses for long-running agents» (11.2025), «Harness design for long-running apps» (03.2026), anthropics/cwc-long-running-agents, гайд по Opus 5.5; описание кита в `.claude/harness-kit/README.md`. Правила исполняются хуками, субагентом и шаблонами.

1. **Контракт до работы.** В стартовом промпте активности или в файле-точке входа репозитория пять строк: Результат / Не делаем / Готово когда / Останавливаюсь если / Кто принимает, плюс строка «Бюджет», если будут прогоны. Контракта нет: написать черновик по `.claude/harness-kit/templates/СТАРТ-шаблон.md` и согласовать с владельцем до первого тяжёлого действия. Новая активность заводится командой `/старт-активности`.
2. **Проверка перед «готово».** Слово «готово» и создание PR разрешены после вердикта `PASS` субагента `оценщик` (свежий контекст, Write и Edit отключены, Bash ограничен текстом промпта) и после открытия конечного артефакта тем способом, каким его увидит читатель. Процедура: `/готово`. Для документов, которые дальше правит человек, достаточно открытого артефакта и вердикта по контракту.
3. **Конец хода.** Если пункты контракта открыты, ничто не ждёт решения владельца и следующий шаг не относится к тяжёлой работе по контракту (длинный прогон, массовая правка, внешняя запись), ход текстом завершением не считается: следующий шаг делается в этом же ходе, отчёт о прогрессе кладётся в то же сообщение. Исключения: свёртка по триггеру владельца и ход, в котором запрошено решение.
4. **Критерии версионируются.** Формулировки пунктов «Готово когда» и пунктов state-файлов (STATE.json, features.json) после согласования не редактируются: изменение означает новую версию с датой и причиной, старая остаётся в истории. В state-файлах меняются только `status` и `evidence`; хук verify-gate, если установлен, не даёт записать в них без прочитанного за последние 30 минут доказательства.
5. **Бюджет.** Сначала один агент; многоагентный прогон, когда соло не справился или цена ошибки высока. У прогона есть потолок (токены или минуты, число агентов), записанный в стартовом промпте. После прогона строка в хэндоффе «Прогоны»: дата, runId, модель и effort, токены, минуты, результат, команда возобновления. Шаблон прогона с учётом бюджета: `.claude/harness-kit/templates/workflow-шаблон.js`.
6. **Судьи калибруются.** Многосудейная фаза заканчивается критиком, который разбирает расхождения судей и устаревшие источники; подсчёт голосов без разбора результатом не считается. Судья проверяет факты по git и файлам; сводные файлы и HANDOFF могут быть устаревшими и доказательством не служат. У каждого источника записывается дата.
7. **Хэндофф перезаписывается.** Верх файла-точки входа из четырёх блоков (Сейчас / Сделано, не повторять / Дальше / Решения владельца, не пересматривать), вытесненное уходит в историю там, где она принята в репозитории. Второй заголовок «читать первым» в одном файле означает стопку; SessionStart-хук показывает её на каждом старте. Шаблон: `.claude/harness-kit/templates/HANDOFF-шаблон.md`.
8. **Влитие кодом.** Хук merge-guard, если установлен, переводит `gh pr merge`, `git merge <ветка>`, push в основную ветку и force-push в режим «спросить владельца»; подтягивание основной ветки в рабочую проходит. Хук видит только команды git и gh; другие системы контроля версий правилом не покрыты, для них действуют местные правила. Где местные правила разрешают самостоятельное влитие или деплой пушем в основную ветку, владелец подтверждает это строкой в хэндоффе, и кит ставится с `--no-merge-guard`.
9. **Ревизия харнеса.** При смене модели и раз в квартал: `/харнесс-ревизия` ищет правила без следа применения, противоречия и устаревшие указатели и предлагает список на удаление.

Хуки в `.claude/hooks/harness/`: SessionStart, Stop (только печать), PreToolUse Bash merge-guard, PostToolUse Read|Bash track-read, PreToolUse Write|Edit verify-gate. Codex исполняет только SessionStart; правила 2, 4, 8 для Codex-сессий держатся на тексте AGENTS.md.
