# WhatsApp Translator

Личный помощник для переписки **русский ↔ сербский** с сохранением обычного номера WhatsApp.

Владелец выбирает контакт и пишет по-русски → сообщение переводится на сербский → отправляется выбранному человеку. Ответ собеседника переводится на русский только для владельца. Самостоятельное продолжение разговора не входит в первую версию.

## Состояние первой поставки

Это **проверяемая основа проекта, не подключённый WhatsApp-бот**:

- TypeScript и SQLite: исходящие, входящие, оригиналы, переводы и статусы.
- Отдельные интерфейсы переводчика и транспорта WhatsApp.
- Закреплённые контакты, защита от повторной отправки по ключу запроса.
- Неопределённый результат отправки отмечается как `unknown`; автоматического повтора нет.
- Входящие сообщения только переводятся; история, собственные сообщения и посторонние чаты пропускаются.
- Демонстрация без сети, ключей, подключения WhatsApp и расхода квот моделей.
- GitHub Actions проверяет сборку, тесты и демонстрацию на Node.js 22/Linux.

Ещё не реализованы: реальный адаптер Baileys, подключение модели перевода, интерфейс владельца, приём статусов доставки WhatsApp и постоянная служба на Hetzner. Демонстрационные фразы берутся из фиксированных примеров и не являются модельным переводом. `sent` означает принятие отправки транспортом, а не подтверждённую доставку.

## Запуск на любом компьютере

Нужен Node.js **22.17+**; целевой сервер использует Node.js 22. GitHub CLI должен иметь доступ к приватному репозиторию.

```sh
gh repo clone alloben812/whatsapp-translator
cd whatsapp-translator
npm ci --ignore-scripts
npm run doctor
npm test
npm run demo
```

`doctor` проверяет только Node.js и SQLite. `demo` создаёт временную БД, выполняет обмен подготовленными фразами и удаляет её. Авторизация в WhatsApp или моделях для этих команд не нужна. SQLite встроен в Node.js; в некоторых версиях Node 22 он выдаёт предупреждение об экспериментальном API.

## Следующие этапы

1. Восстановить административный SSH-доступ к существующему Hetzner с нужного компьютера и проверить фактическое состояние сервера.
2. Подключить репозиторий как отдельный проект в `multimode-agents` для разработки и ревью, сохранив её ограничения квот и исполнителей.
3. Выбрать путь вызова модели перевода. Уже существующие подписочные CLI-входы не являются универсальным API-ключом; пригодность их для быстрых переводов ещё нужно проверить. Платный API не включается автоматически.
4. Реализовать адаптер WhatsApp, сохранение сессии, интерфейс владельца и статусы доставки.
5. Привязать WhatsApp через QR и проверить реальный обмен в явно выбранном чате. До этого не считать интеграцию работающей.
6. После проверки оформить отдельную службу на существующем сервере с приватным доступом к интерфейсу.

## Данные и секреты

Код и документация хранятся в GitHub. SSH-ключи, входы моделей, сессия WhatsApp, база реальной переписки и логи остаются на машине выполнения и исключены из Git. Этот репозиторий не копирует учётные данные `multimode-agents`.

Baileys — неофициальный способ доступа к личному WhatsApp. Возможны сбои и блокировка аккаунта; отсутствие риска не гарантируется. Облачный перевод передаёт выбранные тексты провайдеру модели — это учитывается при выборе адаптера.

Первая реализация хранилища рассчитана на **один экземпляр сервиса на одну БД**. Одновременный запуск двух экземпляров не поддерживается.
