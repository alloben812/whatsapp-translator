# Личный WhatsApp: переводчик русский ↔ сербский

Исследование: 18 сентября 2026 года. Статус: проверена документация; приложение не создано, аккаунт не подключён, сообщения не отправлялись.

## Задача и подтверждённые требования

Пользователь сохраняет обычный личный WhatsApp, текущий номер и существующие переписки. В интерфейсе агента он выбирает собеседника и пишет по-русски. Агент переводит сообщение на сербский и отправляет выбранному человеку. Входящий ответ переводится на русский и показывается владельцу.

Команда владельца на отправку может запускать отправку сразу, без второго подтверждения каждого обычного сообщения. Самостоятельное ведение переговоров и ответы без команды владельца не входят в первую версию.

## Вывод

Технически реализуемо через неофициальный клиент, связанный с личным аккаунтом как дополнительное устройство. Основной компромисс — отсутствие официальной поддержки WhatsApp, возможность поломок после обновлений и риск блокировки аккаунта. Его вероятность по изученным источникам оценить нельзя.

Официальный Cloud API предназначен для WhatsApp Business Platform. Он не является готовым API к обычному личному аккаунту и существующей истории переписки. Для API действует 24-часовое окно свободных ответов после сообщения или звонка пользователя; вне окна требуются утверждённые шаблоны. Поэтому для выбранного сценария он неудобен. Возможности совместной работы Business App и API здесь не исследовались: пользователь подтвердил обычный WhatsApp Messenger.

## Варианты

| Способ | Что даёт | Ограничения |
| --- | --- | --- |
| Baileys | Связанный клиент личного номера; получение и отправка сообщений; Chromium не требуется | Неофициальный протокол; нужны хранение сессии, переподключения, защита от дублей |
| whatsapp-web.js | Связанный клиент на базе WhatsApp Web; получение и отправка | Собственный браузер через Puppeteer; зависимость от изменений WhatsApp Web; неофициальный доступ |
| OpenClaw + WhatsApp | Готовая обвязка подключения через Baileys | Нужна отдельная маршрутизация переводов владельцу; штатный агент отвечает собеседнику; риски Baileys сохраняются |
| Автоматизация интерфейса Desktop/Web | Работа через пользовательский интерфейс | Требует отдельного прототипа; зависит от состояния интерфейса и выбранного чата; надёжность для фоновой работы пока не проверена |
| WhatsApp Business Cloud API | Официальная отправка, входящие сообщения и статусы через webhooks | Бизнес-аккаунт и правила сообщений; не подходит как прозрачное подключение обычного личного WhatsApp |

Для узкой первой версии предлагается локальный сервис на Baileys. Если OpenClaw будет нужен для других задач, можно использовать его WhatsApp-интеграцию и добавить специальный поток перевода. Выбор библиотеки окончательно подтверждается пробным подключением, а не одной документацией.

## Предлагаемое поведение

```text
Владелец: русский текст + выбранный контакт
    → перевод на сербский
    → отправка через связанный клиент
    → обычное сообщение в WhatsApp собеседника

Ответ собеседника в WhatsApp
    → обработчик входящих выбранного чата
    → перевод на русский
    → интерфейс владельца: автор + оригинал + перевод
```

Сербскую латиницу предлагается использовать по умолчанию; это ещё не подтверждённое предпочтение пользователя. Перевод должен сохранять смысл, даты, суммы, имена, степень вежливости и не добавлять обещания.

Интерфейс владельца: небольшая локальная веб-панель или личный Telegram-бот. Выбор ещё открыт. В текущей задаче Codex готовой интеграции WhatsApp нет: поиск каталога плагинов по WhatsApp не вернул результатов. Для постоянного приёма сообщений нужен отдельный работающий сервис, а не только открытый диалог с Codex. Если сервис работает на Mac, перевод останавливается при сне/выключении; для постоянной доступности можно позднее перенести его на сервер.

## Объём первой версии

- Только текст, один-два выбранных личных чата.
- Контакт закреплён по устойчивому идентификатору, перед отправкой видны имя и номер; неоднозначное имя не разрешается догадкой модели.
- Исходящий русский текст, сербский перевод и фактический статус отправки сохраняются в интерфейсе. Принятие запроса не выдаётся за доставку.
- Ответ переводится владельцу; русский перевод не отправляется обратно собеседнику.
- Новые входящие отделяются от истории, собственных исходящих и повторно доставленных событий.
- После разрыва соединения приложение восстанавливается без повторной отправки уже отправленного сообщения. Неопределённый результат показывается явно.
- Содержимое входящих считается данными для перевода, а не командами на управление агентом, смену адресата или отправку.
- Данные сессии остаются в защищённом локальном хранилище; не попадают в Git, отчёты и журналы.
- До подключения модели определяется обработка данных: при облачной модели выбранные тексты передаются её провайдеру; локальная модель требует отдельной проверки качества русского и сербского.
- Голосовые сообщения, звонки, группы и полностью автономные ответы — отдельные последующие задачи.

## Как проверять прототип

1. Проверить русский → сербский и сербский → русский на подготовленных примерах, особенно датах, суммах и вежливых просьбах.
2. Проверить выбор контакта и маршрутизацию на имитированных событиях, исключить отправку русского перевода собеседнику.
3. Проверить повторы, переподключение и неопределённый статус без реальной отправки.
4. После решения пользователя о подключении личного аккаунта привязать устройство и провести явно согласованный тест в выбранном чате.
5. Зафиксировать реальную задержку, корректность доставки и восстановление сессии. До этого не обещать мгновенность или надёжность эксплуатации.
