# Перевод через существующую подписку

Владелец выбрал существующие подписки без платного API: **Claude Sonnet по умолчанию**, **GPT-5.5 как отдельный выбор оператора**. Переключения на другую модель при ошибке нет. Для этого переводчика владелец отдельно разрешил обычные ограничения подписки вместо дополнительного дневного ограничения MultiModeAgents в 20 п.п. Настройки MultiModeAgents и его заданий не меняются.

Это самостоятельный переводчик. Комнаты, проектные пакеты и интерфейс MultiModeAgents для переписки не нужны. Переиспользуются только уже установленные на сервере исполнители, их защищённые входы и блокировка одновременных запусков.

## Контракт приложения

src/translator.ts экспортирует CommandTranslator и createTranslator.

    const { translator, status } = createTranslator({
      command: '/absolute/path/to/operator-owned-broker-client',
      args: [],
      timeoutMs: 75_000,
      maxQueue: 8,
    });

Приложение запускает фиксированный исполняемый файл без shell. Текст не подставляется в аргументы. В stdin передаётся одна строка JSON:

    {"text":"Можно завтра в три?","direction":"ru-sr"}

Ожидается успешный код завершения и единственный JSON-объект:

    {"translation":"Možemo li sutra u tri?"}

Направления — только ru-sr и sr-ru; исходный текст — до 4000 символов, перевод — до 8000. Пустой ответ, посторонние поля, Markdown вокруг JSON, превышение вывода, таймаут и ошибка процесса блокируют отправку. Повтора inference или перехода на API нет. Среда дочернего процесса не наследует ключи, токены, прокси, NODE_OPTIONS или пути сессий.

Одна ограниченная очередь разделяется всеми экземплярами адаптера внутри процесса. Ожидание в очереди также ограничено. Это не заменяет серверную блокировку подписки между процессами. Ошибки нормализуются; исходные сообщения остаются в приватном хранилище приложения.

Наличие status.configured означает только настройку команды. CommandTranslator.probe() вызывает ту же команду с --check, без текста и inference. Broker должен вернуть:

    {"ready":true,"label":"Подписочный переводчик","reason":null}

Проверка не подтверждает будущую доступность квоты, качество перевода или скорость конкретного вызова. При занятости исполнителя возвращается ready: false, reason: "busy". Подробности внешних ошибок и полученная от команды строка label в интерфейс не передаются.

## Серверный broker

scripts/subscription-bridge.py исполняется отдельной доверенной root-службой. Веб-приложению достаточно доступа к её приватному Unix-сокету через фиксированный клиент. Оно не получает произвольный sudo, модельные файлы или право запускать mma-worker.

Конфигурация /etc/whatsapp-translator/translator.json должна принадлежать root с правами 0600:

    {
      "provider": "claude",
      "model": "sonnet",
      "budgetMode": "subscription_limits",
      "serbianScript": "latin"
    }

Сербская латиница остаётся предложенным начальным вариантом; оператор может установить cyrillic. Разрешены только пары claude/sonnet и codex/gpt-5.5. Модели Opus, Astra и другие здесь не допускаются.

Последовательность одного вызова:

1. Взять существующий /var/lib/multimodeagents/model-dispatch.lock и убедиться, что слот соответствующего провайдера и старый общий слот свободны либо достоверно остановлены.
2. Проверить сохранённый подписочный вход существующим provider-runner --check-auth. Проверка не читает и не возвращает содержимое credential-файлов.
3. Создать новый уникальный watr-… run ID и закрытый workspace через существующий mma-worker prepare.
4. Один раз запустить worker с фиксированной моделью и effort: low. Модель получает только фиксированную инструкцию перевода и JSON с текстом, без контактов, ключей WhatsApp или управляющих команд.
5. Ожидать подтверждённую остановку конкретной systemd cgroup. Inference ограничен 30 секундами; worker имеет внешний предел 45 секунд. Весь запрос, включая подготовку, имеет бюджет 54 секунды и дополнительные 5 секунд на отмену.
6. Принять только результат того же run ID, провайдера, модели и effort; строго проверить JSON перевода.

Отмена, неизвестный запуск или истечение срока не создают повтор. Broker пытается остановить конкретный worker через проверку его systemd identity. При недоступности управляющего процесса сохраняются внешний предел и занятый provider slot. Старые PID не используются.

В режиме subscription_limits дополнительный дневной учёт разработческого проекта не применяется. Обычные отказы CLI/провайдера, включая исчерпание квоты, завершают перевод ошибкой: покупки, повышение лимита, смена аккаунта и платный fallback отсутствуют. Broker не обещает гарантированный предел общего расхода подписки.

Не выбранный сейчас режим shared_daily_budget использует существующие chat-cli guard/admit и сохраняет прежний общий допуск без комнаты или проектного задания. Его отказ не подменяется синтетической сверкой.

## Почему можно переиспользовать установленный исполнитель

При проверке исходников MultiModeAgents обнаружен готовый текстовый provider-runner. У Claude отключаются инструменты, MCP и пользовательские расширения; сессия не сохраняется. Codex использует временную read-only сессию app-server, запрет инструментов и сети команд, проверку ожидаемой модели и финального ответа. В обоих случаях окружение очищается от API-ключей и сторонних маршрутов.

Существующий runner записывает закрытые артефакты ответа в свой worker workspace; это реальные тексты переписки, поэтому их нельзя публиковать, добавлять в Git или считать техническим журналом без персональных данных. Срок удаления этих артефактов требует отдельной эксплуатационной настройки. Новая копия credential-файлов не создаётся.

Текущая официальная документация подтверждает программный режим и структурированный вывод [Codex](https://learn.chatgpt.com/docs/non-interactive-mode) и [Claude Code](https://code.claude.com/docs/en/headless). Справка [Claude CLI](https://code.claude.com/docs/en/cli-reference) различает отключение встроенных инструментов через --tools "" и отключение MCP. Поведение конкретного сервера дополнительно определяется установленной версией и уже проверенным runner; актуальная веб-страница сама по себе его не заменяет.

## Проверки и границы

    npm run build
    node --test dist/test/translator.test.js
    python3 test/subscription-bridge.test.py

Node-тесты проверяют границы JSON, отсутствие секрета в окружении, отсутствие shell-интерполяции, общую очередь, ограничения stdout/stderr, остановку группы процессов и readiness без inference. Python-тесты проверяют этапы broker, ограничение моделей, отказ до старта, таймаут, неизвестный старт без повтора, строгий ответ и ограниченные subprocess pipes.

Эти тесты используют локальные фикстуры и не подтверждают живой перевод. Для проверки подключения требуется отдельный реальный короткий вызов модели после установки broker; для WhatsApp — привязка аккаунта и явная команда владельца с выбранным адресатом и текстом.
