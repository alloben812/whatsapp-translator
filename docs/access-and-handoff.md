# Продолжение на другом компьютере и доступ к Hetzner

## Что уже есть

- Приватный репозиторий: <https://github.com/alloben812/whatsapp-translator>.
- Существующая мультиагентка: <https://github.com/alloben812/multimode-agents>.
- Сервер `multimodeagents-pilot` / `165707789`, адрес `2.28.227.134`; административный SSH-пользователь — `mma`, модельные входы принадлежат отдельным runtime-пользователям.
- 18 сентября 2026 года SSH с этого Mac, sudo, Node.js и три основные службы проверены непосредственно на сервере. Входы Codex и Claude подтверждены командами статуса без вызова моделей.
- Проект зарегистрирован в MultiModeAgents и привязан к отдельной комнате **WhatsApp Translator**. Подробности, точные ревизии и ограничения допуска — в [checkpoint](checkpoint-2026-09-18.md).

Новый сервер и новые входы моделей не нужно создавать до проверки существующих. Установку компонентов мультиагентки повторно не запускать.

## Продолжение разработки

На другом компьютере после входа в GitHub:

```sh
gh repo clone alloben812/whatsapp-translator
cd whatsapp-translator
npm ci --ignore-scripts
npm test
npm run demo
```

Открыть эту папку как локальный проект в Codex. Короткий запрос для продолжения:

> Продолжи проект whatsapp-translator. Прочитай README.md, RESEARCH.md, docs/access-and-handoff.md и docs/checkpoint-2026-09-18.md. SSH и регистрация проекта в отдельной комнате MultiModeAgents уже проверялись; сначала перепроверь состояние только чтением. Следующий этап — выбор переводчика и подготовка его проверки. Сохранённый вход в модель не отменяет дневной допуск: последняя проверка запрещала выполнение из-за неполного учёта квот. Не меняй бюджеты и не включай платный API автоматически. WhatsApp ещё не привязан; реальная отправка требует выбранного мной контакта и текста. Не копируй секреты в репозиторий.

## Два разных вида доступа

**GitHub** нужен для кода: `gh auth status` и `gh repo view alloben812/whatsapp-translator`. CLI должен видеть приватный репозиторий.

**SSH** нужен для сервера. Подписочные входы Codex/Claude уже находятся на сервере по документации мультиагентки. Их не нужно пересылать как API-ключи на новый компьютер или в этот проект.

## Вариант A: продолжить с компьютера, у которого уже есть SSH-доступ

На текущем Mac этот вариант уже проверен. Репозиторий находится в `/Users/danilanazarenko/Documents/ChatGPT/Агент для WhatsApp`; существующая копия MultiModeAgents — в `/Users/danilanazarenko/Documents/ChatGPT/MultiModeAgents`.

Из любой папки этого Mac:

```sh
ssh -o IdentitiesOnly=yes -o HostKeyAlgorithms=ssh-ed25519 \
  -o StrictHostKeyChecking=yes \
  -o UserKnownHostsFile=/Users/danilanazarenko/Documents/ChatGPT/MultiModeAgents/.state/hetzner/known_hosts \
  -o BatchMode=yes -o ConnectTimeout=15 \
  -i ~/.ssh/multimodeagents_hetzner_ed25519 mma@2.28.227.134
```

Ключ и `known_hosts` остаются на прежних местах; копировать их в новый проект не нужно. Для чтения ресурсов облака использовать явный контекст: `hcloud --context multimode-agents server describe 165707789`.

При переходе на другой компьютер можно также оставить серверное администрирование на этом Mac. GitHub переносит код; SSH-ключ и локальный `known_hosts` через Git не переносятся.

## Вариант B: дать новому компьютеру собственный SSH-доступ

Предпочтительно создать отдельный ключ нового компьютера, а существующий оставить на прежнем. Команда выполняется локально в терминале нового компьютера:

```sh
ssh-keygen -t ed25519 -a 64 -f ~/.ssh/whatsapp_hetzner_ed25519 -C whatsapp-translator
```

Если файл уже существует, не соглашаться на перезапись без проверки. Пароль ключа, если используется, вводится только в терминале.

Далее:

1. Передать на старый компьютер только публичный файл `~/.ssh/whatsapp_hetzner_ed25519.pub`.
2. Через существующий доверенный SSH-вход добавить его отдельной строкой в `~mma/.ssh/authorized_keys`, сохранив старые ключи. Старую сессию оставить открытой до успешной проверки нового доступа.
3. Перенести существующую запись публичного host key из проверенного `known_hosts` либо независимо сверить отпечаток через Hetzner Console. Не отключать проверку host key.
4. Проверить правило Hetzner Cloud Firewall: по документации SSH разрешался только с конкретного внешнего IP. Если у нового компьютера другой адрес, нужно отдельно добавить его точный `/32` или `/128`. Наличие правильного ключа не обходит firewall.
5. Проверить вход под `mma`, не `root`, и только после этого продолжать настройку.

При подготовке 18 сентября новый ключ и изменения firewall не понадобились. Проверенное правило SSH разрешает `178.222.1.181/32`; уже существующие правила TCP 80/443 обслуживают HTTPS-пульт MultiModeAgents, а не WhatsApp Translator.

## Если переносится существующий приватный ключ

Содержимое ключа не вставлять в чат, GitHub Secrets, issue, README или файл внутри репозитория. Переносить напрямую между своими компьютерами защищённым способом. На целевой машине разместить его в `~/.ssh/`, выставить права `0600` для ключа и `0700` для директории. Публичный host key и запись `known_hosts` нужны отдельно; приватного ключа самого по себе недостаточно для проверки сервера.

Помощнику достаточно сообщить **путь к ключу**, SSH-пользователя и адрес/alias сервера. Значение ключа не требуется. При продолжении на старом компьютере можно сообщить, что существующий доступ уже работает.

## Первая проверка после получения доступа

Только чтение: личность SSH-пользователя, версия Node.js, свободные CPU/RAM/диск, состояние служб мультиагентки, её текущий коммит и доступ к приватному GitHub. Не запускать модель для проверки наличия доступа; использовать существующие read-only проверки, если они установлены.

На этом этапе новый проект не должен перезапускать чужие службы, менять firewall, переавторизовывать модели или отправлять сообщения WhatsApp.

Следующая серверная поставка WhatsApp Translator должна получить отдельный каталог и отдельную службу. Они пока не созданы. Интерфейс владельца сначала доступен через localhost и SSH-туннель. SQLite и сессия WhatsApp включаются в закрытую резервную копию после реализации, а не в Git.
