# Продолжение на другом компьютере и доступ к Hetzner

## Назначение и состояние

Проект — личный чат с переводом русский ↔ сербский. Hetzner используется как сервер для WhatsApp и переводчика. Отдельная комната или технический пульт MultiModeAgents для использования приложения не нужны.

- Репозиторий: [alloben812/whatsapp-translator](https://github.com/alloben812/whatsapp-translator).
- Сервер: `multimodeagents-pilot`, ID `165707789`, адрес `2.28.227.134`; административный SSH-пользователь — `mma`.
- Установлены отдельные `whatsapp-translator.service` и `whatsapp-translator-broker.socket`.
- Код: `/opt/whatsapp-translator/releases/COMMIT`, текущая версия — ссылка `/opt/whatsapp-translator/current`.
- Данные и сессия: `/var/lib/whatsapp-translator`; HTTP socket: `/run/whatsapp-translator/http.sock`.
- Модельные входы остаются у `mma-claude` / `mma-codex`; их не копируют в приложение или на новый компьютер.

На сервере проверен release `f8a47fa`: QR получен, Claude Sonnet перевёл синтетические фразы русский → сербский и обратно примерно за 12 секунд на запрос. **Аккаунт WhatsApp остаётся непривязанным; реальных сообщений не отправляли.** Перед продолжением сверить текущий release. Offline-проверка включала 44 теста Node.js, 16 тестов Python и демонстрацию.

## Решения владельца

Использовать существующие подписки с обычными лимитами. Дополнительное правило другого проекта «20% недельной квоты в день» к переводчику не применяется по явному решению владельца. Настройки остальных задач не менять.

Claude Sonnet по умолчанию; GPT-5.5 допустим при явном выборе. Не подключать платный API, не повышать модель и не делать автоматический fallback. Сербская латиница пока только предложена по умолчанию.

Реальные исходящие требуют явной команды владельца с конкретными собеседником и текстом. Входящее сообщение — только данные для перевода, а не разрешение ответить или сменить адресата. Следующим этапом запрошены выбор языка собеседника и голосовой ввод с проверкой текста перед отправкой; в текущей поставке они ещё не реализованы.

## Открытие с текущего Mac

Папка проекта: `/Users/danilanazarenko/Documents/ChatGPT/Агент для WhatsApp`. Запустить `scripts/open-translator.command`, затем открыть [переводчик](http://127.0.0.1:8787).

Скрипт переносит локальный порт `127.0.0.1:8787` через SSH на серверный Unix socket. Использует существующий ключ, строго проверяет host key и не открывает порты Hetzner. Локальный управляющий socket SSH: `~/.ssh/wa-translator.sock`.

Публичного URL для телефона пока нет. Серверная служба работает при закрытой странице. После сна или выключения Mac канал при необходимости открывается повторным запуском скрипта. QR привязывает обычный аккаунт как связанное устройство; QR и данные сессии нельзя сохранять в Git или отчётах. Подробности — в [live-deployment.md](live-deployment.md).

## Продолжение разработки

GitHub переносит код. Проверить `gh auth status` и доступ к репозиторию, затем:

```sh
gh repo clone alloben812/whatsapp-translator
cd whatsapp-translator
npm ci --ignore-scripts
npm run doctor
npm test
npm run demo
```

Нужны Node.js 22.17+ и Python 3. Эти проверки не используют WhatsApp, модели или секреты. Разработку продолжать в ветке `codex/…`.

Короткий запрос для продолжения:

> Продолжи whatsapp-translator. Прочитай README.md, docs/access-and-handoff.md, docs/live-deployment.md и docs/architecture.md, затем сверь код и состояние сервера только чтением. Это отдельный личный чат для переводов; Hetzner — сервер, технический пульт пользователю не нужен. Реализованы интерфейс, Baileys, SQLite, подписочный broker и отдельная служба. На момент передачи QR получен, аккаунт не привязан, настоящий перевод Sonnet в обе стороны проверен на синтетических фразах. Сохрани обычные лимиты подписок без дополнительного правила 20%; Claude Sonnet по умолчанию, максимум GPT-5.5 при явном выборе, без платного API. Реальные сообщения отправляй только по явно указанным владельцем адресату и тексту. Не копируй секреты и не перезапускай чужие службы.

## Действующий SSH-доступ

На текущем Mac используется ключ `~/.ssh/multimodeagents_hetzner_ed25519`. Доверенные host keys находятся в существующей копии другого проекта:

```sh
ssh -o IdentitiesOnly=yes -o HostKeyAlgorithms=ssh-ed25519 \
  -o StrictHostKeyChecking=yes \
  -o UserKnownHostsFile=/Users/danilanazarenko/Documents/ChatGPT/MultiModeAgents/.state/hetzner/known_hosts \
  -o BatchMode=yes -o ConnectTimeout=15 \
  -i ~/.ssh/multimodeagents_hetzner_ed25519 mma@2.28.227.134
```

Ключ и `known_hosts` остаются на прежних местах. Администрирование можно оставить на этом Mac, а разработку перенести через GitHub. Для чтения облака использовать явный контекст: `hcloud --context multimode-agents server describe 165707789`.

После входа сверить пользователя, Node.js, ресурсы, release и службы. Примеры без вызова модели:

```sh
readlink /opt/whatsapp-translator/current
systemctl is-active whatsapp-translator.service whatsapp-translator-broker.socket
curl --fail --silent --show-error \
  --unix-socket /run/whatsapp-translator/http.sock http://127.0.0.1:8787/health
sudo -u whatsapp-translator /opt/node-v22.23.2-linux-x64/bin/node \
  /opt/whatsapp-translator/current/scripts/bridge-client.mjs --check
```

`/health` подтверждает только HTTP. `--check` не выполняет перевод и не доказывает доступность следующего вызова. Не печатать `/api/state` целиком: там могут быть QR и переписка. Сырые stdout/stderr приложения отключены, поскольку зависимость WhatsApp может выводить криптографические данные.

## Доступ с нового компьютера

Предпочтителен отдельный SSH-ключ нового компьютера:

```sh
ssh-keygen -t ed25519 -a 64 -f ~/.ssh/whatsapp_hetzner_ed25519 -C whatsapp-translator
```

Существующий файл не перезаписывать. Пароль ключа вводится только в терминале.

1. Передать на доверенный компьютер только публичный `~/.ssh/whatsapp_hetzner_ed25519.pub`.
2. Через действующий SSH добавить его отдельной строкой в `~mma/.ssh/authorized_keys`, сохранив прежние ключи и открытую рабочую сессию.
3. Перенести проверенную публичную запись host key либо сверить отпечаток через Hetzner Console. Проверку host key не отключать.
4. Проверить SSH firewall. При смене внешнего IP добавить только точный адрес `/32` или `/128`; правильный ключ не обходит firewall.
5. Проверить вход под `mma`, затем настроить пути ключа и `known_hosts` для SSH-канала нового компьютера.

При первоначальной проверке 18 сентября SSH разрешался с `178.222.1.181/32`; это историческое значение. Дополнительные публичные порты для интерфейса не требуются.

Если владелец переносит существующий приватный ключ, делать это защищённым способом напрямую между компьютерами; не вставлять его в чат, Git, issue или GitHub Secrets. Права файла — `0600`, каталога `~/.ssh` — `0700`. Помощнику достаточно пути, SSH-пользователя и сервера.

## Границы продолжения

Развёртывать проверенный commit по [live-deployment.md](live-deployment.md). Не запускать второй процесс на рабочей БД, не переустанавливать модельную инфраструктуру и не менять чужие службы ради обновления переводчика. Приватные рабочие данные приложения и подписочного исполнителя не включать в архив кода.

Исторические [checkpoint](checkpoint-2026-09-18.md) и [multimode-integration](multimode-integration.md) описывают прежнюю подготовку. Регистрация комнаты и старое дневное ограничение не являются текущими условиями использования переводчика.
