# Контракт первой реализации

## Границы

Один владелец, один процесс, одна SQLite-БД, закреплённый список личных контактов. Без групп, звонков, голосовых сообщений, автономного ответа и автоматического выбора адресата моделью.

`Translator` получает текст и направление `ru-sr` или `sr-ru`. `Transport` получает уже выбранный устойчивый ID контакта и переведённый текст. В демонстрации оба адаптера являются локальными фикстурами.

## Исходящее сообщение

Команда владельца содержит `contactId`, `text` и уникальный `idempotencyKey`. Ключ сохраняется до первого внешнего действия и привязывается к точному исходному тексту и контакту. Повтор того же запроса возвращает существующую запись; другой текст или адресат с тем же ключом — конфликт.

```text
translating → sending → sent
      │           │
      └→ failed   └→ unknown
```

Ошибка или пустой результат модели блокируют отправку. Любая ошибка после входа в транспорт трактуется консервативно: отправка могла произойти, поэтому результат `unknown`, без повторной попытки. После перезапуска `sending` становится `unknown`, а незавершённый перевод — `failed`.

`sent` пока означает успешный ответ транспорта. Состояния `delivered/read`, корреляция по заранее сохранённому ID WhatsApp и сверка `unknown` будут добавлены вместе с реальным адаптером. Текущая основа не обещает exactly-once доставку на стороне WhatsApp.

## Входящее сообщение

Обрабатываются только новые текстовые сообщения разрешённых личных контактов. Ключ дедупликации — ID сообщения вместе с контактом. История, собственные исходящие и неразрешённые чаты не запускают перевод.

Перевод `sr-ru` сохраняется для владельца. Входящий обработчик не вызывает отправку и не отвечает собеседнику. Текст входящего, включая инструкции или просьбу написать другому, остаётся данными для перевода. Реальный адаптер модели дополнительно должен ограничить ответ переводом, без инструментов.

## Хранение

Сохраняются оригинал, перевод, направление, контакт, время, статус, ID транспорта и нормализованный код ошибки. Сырые ошибки внешних провайдеров не возвращаются и не пишутся в журнал: в них могут быть ключи или текст запроса.

Дедупликация переживает закрытие и повторное открытие БД. База реальной переписки не шифруется самим SQLite; при эксплуатации она должна находиться в приватном каталоге с отдельным доступом и закрытой резервной копией.

Открытие хранилища выполняет восстановление состояний: **две копии сервиса на одной БД не поддерживаются**. Серверная обвязка должна запускать один экземпляр.

## Что проверяют тесты

Отправка в выбранный чат, повторы запросов, конфликт ключа, повтор после перезапуска, неопределённый результат отправки, ошибка перевода, маршрутизация входящих только владельцу, фильтрация истории/собственных/чужих сообщений и параллельные запросы.

Тесты и демонстрация работают без сети и секретов. Реальные WhatsApp и модель требуют отдельной проверки после подключения.
