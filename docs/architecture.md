# Архитектура личного переводчика

## Границы приложения

Один владелец, один процесс, одна SQLite-БД и сохранённый список личных контактов. Владелец явно выбирает адресата; его русский текст переводится на сохранённый язык собеседника и отправляется. Входящий текст переводится на русский только для владельца, без автоматического ответа.

Поддерживаются новые обычные текстовые сообщения. История, собственные сообщения, группы, статусы, медиа, подписи, реакции, редактирования и служебные сообщения не переводятся. Исходный текст ограничен 4000 символами, перевод — 8000. Язык задаётся отдельно для каждого контакта; доступны 16 вариантов. Голосовой ввод распознаёт русский текст до 60 секунд и возвращает его в черновик без отправки.

Реальные адаптеры реализованы. аккаунт привязан владельцем, соединение установлено; настоящий перевод и локальное распознавание проверены на синтетических фразах; живая переписка ещё не подтверждена.

## Компоненты

```text
Браузер → localhost:8787 → SSH → приватный HTTP Unix socket
  → HTTP-приложение → TranslationService → SQLite
                         │            │
                         │            └→ WhatsAppConnection → Baileys
                         └→ CommandTranslator → bridge-client
                           → приватный broker socket → подписочный worker
```

- `web/`: адаптивный интерфейс, QR, контакты, оригиналы/переводы и статусы.
- `src/http-app.ts`, `src/server.ts`: HTTP-контракт, CSRF, Host/Origin, авторизация, запуск и остановка.
- `src/service.ts`, `src/store.ts`: команды, перевод, SQLite, дедупликация и восстановление.
- `src/transcription.ts`, `scripts/transcribe.py`: ограниченный локальный Whisper CPU/int8, приватный временный файл, один запрос за раз; готовый текст возвращается владельцу.
- `src/whatsapp.ts`: QR/сессия Baileys, проверка номера, фильтрация, сопоставление идентификаторов и подтверждения.
- `src/translator.ts`, `scripts/bridge-client.mjs`, `scripts/subscription-bridge.py`: ограниченный JSON-вызов подписочного исполнителя.

Номер проверяется WhatsApp при добавлении контакта и сохраняется как `digits@s.whatsapp.net`. Модель получает текст и проверенные коды `sourceLanguage` / `targetLanguage`, не выбирает адресата. Языки сохраняются в сообщении до первого асинхронного действия; смена настройки контакта не меняет историю, повтор исходящего или повторный перевод входящего. Для входящих LID используются протокольные данные и сохранённое сопоставление Baileys; противоречие отклоняется.

## Список чатов

События `contacts.*`, `chats.*`, metadata истории и новых сообщений пополняют таблицу `discovered_chats`: проверенный телефонный JID, имя, доступные время и краткий текст последнего сообщения. Это отдельная директория, а не список разрешённых для перевода контактов. Неразрешённые LID, группы и служебные адреса не становятся получателями.

При первом соединении процесса и по **Обновить чаты** выполняется ограниченный по времени app-state resync Baileys. Он не удаляет сессию и не вызывает отправку сообщений. Уже обработанные библиотекой версии app-state могут потребовать отдельного восстановления снимка оператором, если раньше события не сохранялись.

`POST /api/chats/open` включает выбранный известный чат в `contacts`; сохраняет ранее выбранные язык и имя. Импорт метаданных и открытие чата не вызывают модель, не переводят историю и ничего не отправляют. В списке доступны поиск, имена и имеющиеся previews; полный архив обычного WhatsApp пока не загружается.

## Исходящее сообщение

Команда содержит `contactId`, точный `text` и `idempotencyKey`. Ядро резервирует ключ в БД до первого асинхронного действия. Повтор возвращает существующую запись; другой текст или адресат с тем же ключом вызывает конфликт. Защита переживает перезапуск и повтор HTTP-запроса браузером.

```text
translating → sending → sent → delivered → read
     │            │
     └→ failed    ├→ unknown → sent / delivered / read по подтверждению
                  └→ failed, если отправка точно не начиналась
```

Ошибка или недопустимый перевод даёт `failed` без отправки. Перед обращением к транспорту ядро сохраняет `sending` и заранее созданный `remoteId`, затем передаёт этот ID Baileys. Подтверждение можно принять, даже если оно пришло раньше завершения вызова отправки.

`WHATSAPP_NOT_CONNECTED` до сетевой отправки даёт `failed / whatsapp_disconnected`: сообщение точно не отправлено. Неопределённая ошибка после начала отправки даёт `unknown / uncertain_delivery`, без автоматического повтора. Полученное подтверждение не заменяется более ранним статусом из позднего ответа или ошибки.

`sent` означает принятие сообщения транспортом; `delivered` и `read` выставляются по событиям WhatsApp. Подтверждение ищется по контакту и `remoteId`, статусы меняются только вперёд. `unknown` может быть уточнён поздним подтверждением. Активная сверка истории и гарантия exactly-once доставки не реализованы.

Браузер сохраняет неопределённый запрос в `sessionStorage`. **Проверить результат** читает прежний ключ, ничего не отправляя. Для исходящего `failed` действие **Вернуть текст в поле** восстанавливает черновик только в том же выбранном чате, защищает другой черновик и требует отдельной команды отправки.

## Входящее сообщение

Обрабатываются события `notify` с обычным текстом от добавленных контактов. Ключ дедупликации — `(contactId, remoteId)`. Начальная и недавняя история используются только для директории чатов; собственные исходящие, история и невыбранные чаты не запускают перевод.

```text
translating → received
     └→ failed → translating → received, по ручной команде повторить перевод
```

Оригинал записывается до перевода. `received` означает сохранённый перевод для владельца. `retryIncoming(id)` разрешён только для входящего `failed` из добавленного чата и никогда не вызывает отправку. Инструкции внутри сообщений остаются данными; модель не имеет инструментов или права менять адресата.

## Соединение и переводчик

Первое подключение начинается по нажатию **Подключить WhatsApp**. QR виден владельцу, сессия хранится в приватном каталоге. При следующем старте действующая привязка подключается повторно. Временные разрывы допускают ограниченное переподключение; выход/отклонение сессии требуют действий владельца. Повторные отправки в адаптере отключены. Ошибка сохранения сессии останавливает соединение.

Выбор владельца: Claude Sonnet, либо GPT-5.5 при явном выборе; обычные лимиты подписки без дополнительного правила «20% недельной квоты в день». Политика других заданий не меняется. Платного API и автоматической замены модели нет. Broker поддерживает сербскую латиницу и кириллицу; латиница пока предложена по умолчанию.

Приложение вызывает фиксированный executable без shell и наследования API-ключей. Broker проверяет доверенный release и конфигурацию, использует существующие блокировку/слоты worker и изолированного пользователя модели. Учётные данные не копируются в приложение. Вызовы сериализуются, ограничены очередь, время и вывод, проверяется остановка процессов. Занятый слот или неопределённое завершение блокирует новый вызов. `--check` не выполняет inference и не гарантирует успех следующего перевода.

## HTTP и данные

HTTP слушает `/run/whatsapp-translator/http.sock`. Доступ обеспечивают права ОС и SSH владельца с `127.0.0.1:8787`; публичного адреса пока нет. Live-режим требует пароль также при Unix socket; установленная служба получает scrypt-хеш через systemd `LoadCredential`. TCP слушает loopback. **Выйти** отзывает браузерную сессию; срок сессии — 12 часов. POST требует `X-CSRF-Token` и JSON, кроме raw audio у `/api/transcribe`; проверяются Host/Origin. При включённом пароле используются HttpOnly/SameSite-сессия и ограничение попыток входа. Кэширование отключено, текст выводится через `textContent`, CSP ограничивает ресурсы.

Операции: `POST /api/login`, `/api/logout`, `/api/connect`, `/api/contacts`, `/api/chats/sync`, `/api/chats/open`, `/api/contact-language`, `/api/send`, `/api/retry-translation`, `/api/transcribe`. `GET /api/state` возвращает состояние, директорию чатов, состояние её синхронизации, активные контакты и последние 500 сообщений. `requestKey` дополнительно возвращает сохранённый запрос за пределами этого окна. `/health` проверяет только HTTP.

SQLite сохраняет контакты, оригиналы, переводы, время, статусы, ID транспорта, ключ запроса и нормализованный код ошибки. При открытии БД `translating` становится `failed / interrupted_translation`, `sending` — `unknown`. Служба использует `flock`; второй процесс на той же БД не поддерживается.

Данные хранятся в `/var/lib/whatsapp-translator`, root-owned release отделён от переписки. SQLite самостоятельно не шифрует сообщения. Тексты также остаются в приватных каталогах подписочного worker. Автоматическая очистка, зашифрованная резервная копия и проверенное восстановление пока не реализованы. Сырые stdout/stderr приложения отключены из-за логирования криптографических данных зависимостью WhatsApp.

Установка описана в [live-deployment.md](live-deployment.md), перенос доступа — в [access-and-handoff.md](access-and-handoff.md).

## Проверки

Последняя зафиксированная offline-проверка: тесты Node.js и Python (точные результаты в checkpoint) через `npm test`, плюс `npm run demo`. Проверяются маршрутизация, дедупликация, параллельные запросы, подтверждения, неизвестная отправка, восстановление, фильтрация, HTTP/CSRF, очереди и границы broker на подменённых зависимостях. UI проверялся с фикстурами, включая мобильный экран и потерянный HTTP-ответ.

Настоящий перевод, QR, привязка и обмен с выбранным владельцем собеседником фиксируются отдельно. QR получен, русский ↔ сербский Sonnet и Whisper WAV/WebM проверены. Владелец подтвердил привязку; реальный обмен требует его конкретных адресата и текста.
