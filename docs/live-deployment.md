# Живой переводчик на Hetzner

Приложение — отдельный чат для владельца. На выбранный контакт отправляется перевод явной команды владельца на язык контакта; входящие тексты переводятся на русский только в этом чате. Разработческий пульт MultiModeAgents для использования приложения не нужен.

## Решения владельца

- Использовать существующие подписки; не подключать платный API.
- Для перевода — Claude Sonnet по умолчанию; допустим GPT-5.5 при явном выборе, без автоматической замены модели.
- Для переводчика действуют обычные лимиты подписок. Дополнительное правило другого проекта «20% недельной квоты в день» к нему не применяется. Настройки и допуск остальных задач не меняются.
- Для каждого контакта выбирается один из 16 вариантов языка; новый контакт по умолчанию использует сербскую латиницу.

## Как открыть с текущего Mac

Запустить `scripts/open-translator.command` из этой Git-копии, затем открыть <http://127.0.0.1:8787> в браузере. Скрипт создаёт приватный SSH-канал с существующим ключом и строгой проверкой host key. Не открывает порты Hetzner и не запускает модель. Повторный запуск использует существующий канал; после выключения/сна Mac при необходимости запустить снова.

В приложении нажать **Подключить WhatsApp**. На телефоне: WhatsApp → Настройки → Связанные устройства → Привязка устройства; отсканировать QR на странице. QR не сохранять в Git или отчётах. Затем добавить собеседника по точному номеру с кодом страны, выбрать его и ввести русский текст. Можно надиктовать русский текст кнопкой **Надиктовать** (до 60 секунд), завершить запись и проверить черновик. Кнопка **Перевести и отправить** — явная команда отправки выбранному человеку. Ошибка перевода блокирует отправку; неопределённая отправка автоматически не повторяется.

Страница пока доступна с этого Mac через SSH. Публичного URL для телефона ещё нет. После привязки сервер продолжает принимать сообщения при выключенном Mac; закрытие страницы не завершает серверную службу. Входящие обрабатываются только от добавленных собеседников, с момента подключения; старая история не импортируется. Первые реальные сообщения и качество выбранного чата нужно проверить с владельцем.

## Изоляция и данные

- Служба `whatsapp-translator.service`, отдельный системный пользователь `whatsapp-translator` без sudo.
- Код: `/opt/whatsapp-translator/releases/COMMIT`, ссылка `current`; владелец root, приложение не может менять код.
- Данные: `/var/lib/whatsapp-translator` (`0700`), SQLite и `whatsapp-auth` исключены из Git.
- HTTP слушает только `/run/whatsapp-translator/http.sock`: каталог `0750`, socket `0660`, группа `whatsapp-translator`. В группу добавлен только административный пользователь `mma`; пользователи моделей не получают доступ к переписке или QR.
- TCP-режим требует `WA_PASSWORD`. В текущем Unix-socket режиме доступ обеспечивает ОС и доверенный SSH; браузерные изменения дополнительно требуют CSRF, правильного Host/Origin. Страницы и данные не кэшируются.
- Raw stdout/stderr службы отключены из-за прямого логирования внутри transitive libsignal. Состояние соединения и нормализованные ошибки доступны интерфейсу; смотреть сырые криптографические логи нельзя.

## Как устроен перевод

Приложение передаёт только текст и направление через фиксированный `bridge-client.mjs` в `/run/whatsapp-translator-broker.sock`. Socket доступен группе приложения. Root socket-unit вызывает фиксированный `/usr/local/sbin/whatsapp-translation-socket`, который проверяет неизменяемый release и запускает JSON broker.

Broker использует существующий `mma-worker` как изолированный исполнитель: без инструментов модели, произвольных команд, выбора получателя или API fallback. Модель видит только текст для перевода. Существующие credentials остаются у `mma-claude` / `mma-codex`; они не читаются веб-приложением и не копируются. Вызовы сериализуются с другими заданиями через существующую блокировку и слоты; занятый или неопределённый слот блокирует новый вызов.

Один запрос ограничен 4000 символами, 30 секундами inference и 45 секундами worker. Внешний broker имеет отдельный общий deadline и отмену. Отказ подписки не заменяется более дорогой моделью и не повторяется автоматически. Сохранённый вход подтверждается через `--check` без inference; это не гарантия доступности модели на каждом последующем запросе.

Рабочие пакеты и результаты вызовов остаются также в закрытых каталогах существующего worker. Нужно учитывать их при политике хранения приватной переписки; автоматическая очистка/восстановление зашифрованной резервной копии в этой версии не реализованы.

## Развёртывание и проверка

Собрать и проверить точный commit на компьютере оператора:

```sh
npm ci --ignore-scripts
npm test
npm run demo
```

Архивировать только Git-файлы выбранного commit и собранный `dist/`, без `.state`, ключей, базы и сессии. На macOS для `dist` использовать `COPYFILE_DISABLE=1 tar --no-xattrs`, чтобы не переносить extended attributes. На сервере создать новый root-owned каталог `/opt/whatsapp-translator/releases/FULL_COMMIT`, распаковать туда, установить runtime зависимости через `npm ci --omit=dev --ignore-scripts` и выполнить от root:

```sh
bash /opt/whatsapp-translator/releases/FULL_COMMIT/infra/install.sh FULL_COMMIT
```

Установщик создаёт только пользователя/данные/units этого приложения, добавляет `mma` в группу приватного socket и сохраняет существующую конфигурацию при обновлении. Перезапускается только `whatsapp-translator.service`; firewall, gateway и службы другого проекта не меняются. Установку выполнять только после проверки конкретного commit; это не read-only диагностика.

Пример проверки без модели:

```sh
sudo -u whatsapp-translator /opt/node-v22.23.2-linux-x64/bin/node \
  /opt/whatsapp-translator/current/scripts/bridge-client.mjs --check
systemctl is-active whatsapp-translator.service whatsapp-translator-broker.socket
```

Результат настоящего тестового перевода и проверку QR фиксировать отдельно от offline тестов. Реальную отправку подтверждать только по выбранному владельцем контакту, тексту и наблюдаемому результату.

## Проверенный голосовой ввод

На этом сервере установлен локальный faster-whisper small/int8, без внешнего API. На четырёхсекундной синтетической русской записи WAV/WebM получен правильный текст примерно за 11 секунд. Пик памяти службы с распознавателем составил 751448064 байта (около 717 MiB); это один замер, не гарантия задержки на любой записи. Реальный микрофон владельца ещё не проверен. Установка закреплённых зависимостей и модели — `infra/install-speech.sh`; текущая конфигурация и ограничения описаны в [voice-input.md](voice-input.md).
