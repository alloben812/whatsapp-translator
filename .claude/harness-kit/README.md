# Харнесс-кит

Версия: см. `VERSION`. Набор файлов для репозитория, в котором работает агент (Claude Code; Codex частично). Кит закрепляет кодом девять правил долгих агентных окон, которые иначе держатся только на тексте инструкций и забываются: контракт до работы, проверка перед «готово», конец хода действием, версия критериев, бюджет прогона, калибровка судей, перезаписываемый верх хэндоффа, влитие по явному ОК, ревизия правил. Правила кита дополняют правила репозитория и уступают им при расхождении.

**Для кого.** Для владельца репозитория, где агент работает подолгу и в несколько окон: многодневные задачи, хэндоффы между сессиями, многоагентные прогоны, PR.

**Какие сбои закрывает.** «Готово» без критерия; хэндофф, обросший стопкой заголовков «читать первым»; статус «пройдено» без открытого доказательства; самооценка исполнителя вместо проверки; прогон без потолка по токенам; влитие в основную ветку по одному лишь тексту правила; окно, закончившееся без коммита; правила, которые только растут.

**Что получите.** После установки каждая сессия стартует с печати состояния (ветка, незакоммиченное, стопки); пометка «пройдено» в state-файле требует прочитанного доказательства; слово «готово» и PR проходят через скептика со свежим контекстом; влитие и force-push останавливаются до слова владельца; конец окна показывает, что не закоммичено.

**Установка.** Порядок, флаги и что должно сойтись: `ДЛЯ-ПОЛУЧАТЕЛЯ.md`; готовый промпт для вашего агента: `ПРОМПТ-ДЛЯ-АГЕНТА.md`. Ставит `install.sh`, проверяет `selfcheck.sh`, убирает `uninstall.sh`. После установки этот README лежит в `.claude/harness-kit/README.md`, изменения между версиями в `CHANGELOG.md`.

## Словарь

- **Окно**: одна сессия агента от старта до свёртки.
- **Активность**: задача длиннее одного окна со своей веткой, хэндоффом и стартовым промптом.
- **Хэндофф**: файл-точка входа (HANDOFF.md, STATUS.md, SESSION.md), по которому следующее окно продолжает без пересказа.
- **Стопка**: несколько заголовков «читать первым» в одном файле: признак, что хэндофф не перезаписывают, а наслаивают.
- **Прогон**: многоагентный запуск (Workflow) с потолком токенов и агентов.
- **Доказательство**: файл, подтверждающий результат: лог, чекпоинт, скриншот, отчёт, артефакт прогона.

## Из чего состоит

| Файл | Событие или вызов | Что делает |
|---|---|---|
| `.claude/hooks/harness/session-start-harness.sh` | SessionStart (Claude и Codex) | Печатает ветку, незакоммиченное, стопки заголовков «читать первым» в закоммиченных `*HANDOFF.md`, `.claude/commands/*.md` и файлах из `--entry`, напоминание про контракт; на основной ветке при установленном merge-guard напоминает работать в ветке; с 20:00 до 07:00 при флаге `--night-rule` напоминает про бюджет. В git не пишет; на startup и clear обнуляет журнал `.claude/.evidence-reads`, если гейт установлен |
| `.claude/hooks/harness/stop-uncommitted.sh` | Stop | Показывает владельцу число незакоммиченных файлов и незапушенных коммитов (без remote только незакоммиченное). В git не пишет |
| `.claude/hooks/harness/merge-guard.sh` | PreToolUse, Bash (если установлен) | `gh pr merge`, `git merge <ветка>`, push в основную ветку (refspec `HEAD:<ветка>`, `refs/heads/<ветка>`, `git push origin HEAD` и `git push` с основной ветки), force-push получают решение «спросить владельца». Подтягивание основной ветки в рабочую проходит. Основные ветки: флаг `--base` (список через запятую, заменяет main и master), иначе origin/HEAD, иначе main и master |
| `.claude/hooks/harness/track-read.sh` | PostToolUse, Read и Bash (если установлен) | Записывает чтение файла-доказательства (лог, чекпоинт, скриншот, отчёт, `artifacts/`, `results/`) в `.claude/.evidence-reads`; из Bash только команды чтения. Файл с именем state-файла доказательством не считается, в какой бы папке он ни лежал |
| `.claude/hooks/harness/verify-gate.sh` | PreToolUse, Write и Edit (если установлен) | Запрещает запись в файлы с именами STATE.json, state.json, features.json, test-results.json (в любой папке; список меняется переменной `RESULTS_FILES_RE`), если за 30 минут в этом checkout не прочитано доказательство |
| `.claude/hooks/harness/kill-switch.sh` | PreToolUse, все инструменты (если установлен) | Пока в корне лежит файл `AGENT_STOP`, каждый вызов инструмента отклоняется с текстом файла; агент записывает состояние и заканчивает ход |
| `.claude/agents/оценщик.md` | субагент, вызывается `/готово` | Скептик со свежим контекстом: контракт, diff, доказательства, вердикт `PASS` или `NEEDS_WORK` первой строкой. Write и Edit отключены, Bash ограничен текстом промпта |
| `/готово`, `/старт-активности`, `/харнесс-ревизия` | команды Claude Code | Процедура перед «готово»; инициализация активности с контрактом; ревизия правил при смене модели |
| `.claude/harness-kit/templates/` | шаблоны | Стартовый промпт (контракт, Шаг 0, бюджет), хэндофф (четыре перезаписываемых блока), Workflow-прогон с учётом бюджета (нужен инструмент Workflow) |
| `.claude/harness-kit/` | служебное | `VERSION`, `flags` (флаги установки), `manifest` (хэши файлов кита), маркеры `night-rule`, `entry-files`, `base-branch`, `evidence-exclude` по флагам |

## Как это работает в окне

1. Старт: хук печатает состояние и стопки, напоминает про контракт.
2. Новая активность: `/старт-активности <имя>` заводит ветку и дом по правилам этого репозитория, контракт из пяти вопросов владельцу, первый коммит.
3. Работа одной единицей между хэндоффами; у прогона записан потолок, после прогона записана цена.
4. Перед «готово»: `/готово`, то есть оценщик, артефакт тем способом, каким его увидит читатель, хэндофф, коммит.
5. Конец окна: Stop-хук покажет, что не закоммичено.

## Настройка

Хуки читают переменные окружения и файлы в `.claude/harness-kit/`: `EVIDENCE_RE` (что считать доказательством), `EVIDENCE_EXCLUDE_RE` или файл `evidence-exclude` (что не считать), `RESULTS_FILES_RE` (какие файлы защищает verify-gate), `EVIDENCE_WINDOW_MIN` (окно, по умолчанию 30), `HARNESS_BASE_BRANCH` или файл `base-branch` (основная ветка). Переменные задаются в `env` секции `settings.json` Claude Code.

## Ограничения

Хуки защищают от невнимательности. Границы безопасности они не дают: verify-gate обходится записью через Bash, merge-guard нестандартным написанием команды. Хуки ставятся в проектный `.claude/settings.json` и после влития действуют у каждого, кто открывает репозиторий в Claude Code (bash и python3 на каждое событие); для одного человека их можно перенести в `.claude/settings.local.json`. Codex исполняет только SessionStart. Хуки действуют с ветки, где они влиты. Журнал доказательств общий на checkout: второе окно в том же checkout видит его и обнуляет на старте. Тексты кита на русском. Проверено на Linux и macOS; Windows не поддерживается.

## Обновление и удаление

Повторный запуск `install.sh` из папки кита (распакованный пакет новой версии): без флагов берёт флаги прошлой установки из `.claude/harness-kit/flags`, с флагами задаёт новый полный набор. Хуки, шаблоны и README перезаписываются без вопроса (свои настройки держите в переменных и маркерах, не в правках хуков); файлы в `agents/` и `commands/`, отличающиеся от кита, останавливают установку до `--force`. Блок между маркерами `harness-kit:start/end` в CLAUDE.md обновляется, хуки не дублируются; изменения формулировок правил между версиями записаны в `CHANGELOG.md`. Проверка установки: `selfcheck.sh <repo>`, все строки PASS. Удаление: `uninstall.sh <repo>`.
