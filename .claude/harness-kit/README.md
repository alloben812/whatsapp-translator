# Харнесс-кит (установлен из alloben812/job_alloben)

Набор файлов, который закрепляет кодом девять правил долгих агентных окон: контракт до работы, проверка перед «готово», конец хода действием, версия критериев, бюджет прогона, калибровка судей, перезаписываемый верх хэндоффа, влитие по явному ОК, ревизия правил. Правила кита дополняют правила этого репозитория и уступают им при расхождении. Полный разбор, откуда взялись правила и какие сбои они закрывают: `scripts/окружение/harness-kit/README.md` и `разбор/` в job_alloben.

## Из чего состоит

| Файл | Событие или вызов | Что делает |
|---|---|---|
| `.claude/hooks/harness/session-start-harness.sh` | SessionStart (Claude и Codex) | Печатает ветку, незакоммиченное, стопки заголовков «читать первым» в файлах-точках входа, напоминание про контракт и бюджет. Только чтение |
| `.claude/hooks/harness/stop-uncommitted.sh` | Stop | Показывает владельцу число незакоммиченных файлов и незапушенных коммитов. В git не пишет |
| `.claude/hooks/harness/merge-guard.sh` | PreToolUse, Bash (если установлен) | `gh pr merge`, `git merge <ветка>`, push в main, force-push получают решение «спросить владельца». `git merge main` в рабочую ветку проходит |
| `.claude/hooks/harness/track-read.sh` | PostToolUse, Read и Bash | Записывает чтение файла-доказательства (артефакт прогона, лог, чекпоинт, скриншот, `artifacts/`) в `.claude/.evidence-reads` |
| `.claude/hooks/harness/verify-gate.sh` | PreToolUse, Write и Edit | Запрещает запись в STATE.json, state.json, features.json, test-results.json, если за 30 минут в этом checkout не прочитано доказательство |
| `.claude/hooks/harness/kill-switch.sh` | PreToolUse, все инструменты (если установлен) | Пока в корне лежит файл `AGENT_STOP`, каждый вызов инструмента отклоняется с текстом файла; агент записывает состояние и заканчивает ход |
| `.claude/agents/оценщик.md` | субагент, вызывается `/готово` | Скептик со свежим контекстом: контракт, diff, доказательства, вердикт `PASS` или `NEEDS_WORK` первой строкой. Write и Edit отключены, Bash ограничен текстом промпта |
| `/готово`, `/старт-активности`, `/харнесс-ревизия` | команды | Процедура перед «готово»; инициализация активности с контрактом; ревизия правил при смене модели |
| `.claude/harness-kit/templates/` | шаблоны | Стартовый промпт (контракт, Шаг 0, бюджет), хэндофф (четыре перезаписываемых блока), Workflow-прогон с учётом бюджета |

## Как это работает в окне

1. Старт: хук печатает состояние и стопки, напоминает про контракт и бюджет.
2. Новая активность: `/старт-активности <имя>` заводит ветку и дом по правилам этого репозитория, контракт из пяти вопросов владельцу, первый коммит.
3. Работа одной единицей между хэндоффами; у прогона записан потолок, после прогона записана цена.
4. Перед «готово»: `/готово`, то есть оценщик, артефакт тем способом, каким его увидит читатель, хэндофф, коммит.
5. Конец окна: Stop-хук покажет, что не закоммичено.

## Ограничения

Хуки защищают от невнимательности. Границы безопасности они не дают: verify-gate обходится через Bash, merge-guard нестандартным написанием команды. Codex исполняет только SessionStart. Хуки действуют с ветки, где они влиты. Журнал доказательств общий на checkout: второе окно в том же checkout видит его и обнуляет на старте.

## Обновление

Повторный запуск `install.sh` из job_alloben с теми же флагами обновляет файлы и блок между маркерами `harness-kit:start/end` в CLAUDE.md, ничего не дублируя. Версия в `VERSION`.
