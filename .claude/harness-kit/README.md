# Харнесс-кит

Набор файлов, который закрепляет кодом семь правил долгих агентных прогонов: контракт до работы, проверка перед «готово», версия критериев, бюджет, калибровка судей, перезаписываемый хэндофф, влитие по явному ОК. Собран 28.10.2026 по разбору поста @beamnxw (06.10.2026) и первоисточников Anthropic; карта решений и аудит нашей практики лежат в разборе `harness-карта-решений-2026-10-28.md` (передан владельцу файлом, копия в `разбор/`).

## Из чего состоит и зачем каждая часть

| Файл | Событие или вызов | Что делает | Какой сбой закрывает |
|---|---|---|---|
| `hooks/session-start-harness.sh` | SessionStart (Claude и Codex) | Печатает ветку, незакоммиченное, стопки заголовков «читать первым» в HANDOFF и стартовых промптах, напоминание про контракт и бюджет. Только чтение | Формат хэндоффа без принудителя отрастает: TMMi набрал семь «актуальных точек» за месяц после консолидации, рутины пять «читать первым» |

| `hooks/merge-guard.sh` | PreToolUse, Bash | `gh pr merge`, `git merge <ветка>`, push в main, force-push получают решение «спросить». `git merge main` в рабочую ветку проходит | Протокол влития держался на тексте; самовливание в main случалось дважды (агент рутин) |
| `hooks/track-read.sh` | PostToolUse, Read | Записывает чтение файла-доказательства (чекпоинт, отчёт, лог, снимок, скриншот) в `.claude/.evidence-reads` | Основа для verify-gate |
| `hooks/verify-gate.sh` | PreToolUse, Write и Edit | Запрещает запись в STATE.json, state.json, features.json, test-results.json, пока в сессии не прочитано доказательство; после записи журнал обнуляется | «Пройдено» без доказательства: профиль petrov в хэндоффе при другом на машине, нули в журнале после «живой приёмки» |
| `hooks/kill-switch.sh` | PreToolUse, все инструменты (флаг `--with-kill-switch`) | Пока в корне лежит файл `AGENT_STOP`, каждый вызов инструмента отклоняется с текстом файла как причиной; агент пишет состояние и заканчивает ход | Ночные прогоны без присмотра (tms-impact-select): остановить одним `touch AGENT_STOP`, не убивая процесс |

## Как это работает в окне

1. Окно стартует: хук печатает состояние и стопки, напоминает про контракт и бюджет.
2. Новая активность: `/старт-активности <имя>` заводит дом, HANDOFF и стартовый промпт, задаёт владельцу пять вопросов контракта, делает первый коммит.
3. Работа идёт одной единицей между хэндоффами. Многоагентный прогон стартует со скелета `workflow-шаблон.js` с бюджетом; после прогона строка в HANDOFF «Прогоны».
4. Пометка «пройдено» в state-файле возможна только после прочтения доказательства (verify-gate).
5. Перед словом «готово»: `/готово`, то есть оценщик, артефакт глазами читателя, HANDOFF, коммит. Влитие только по явному ОК; merge-guard спросит.
6. Конец окна: Stop-хук покажет, что не закоммичено и не запушено.
7. Раз в квартал или при смене модели: `/харнесс-ревизия`.

## Ограничения, о которых надо знать

- Хуки это защита от невнимательности, не граница безопасности: verify-gate обходится через Bash, merge-guard через нестандартное написание команды. Anthropic называет свои хуки «teaching example», наши такие же.
- Codex исполняет только SessionStart. Stop, PreToolUse и PostToolUse в Codex-сессиях не действуют; там правила держатся на блоке в AGENTS.md.
- Хуки действуют с ветки, где они влиты; до влития в main они работают только в сессиях этой ветки.
- Скрипт Workflow не имеет доступа к файлам и часам: STOP-файл и STEER-файл внутри прогона нереализуемы. Остановка прогона это остановка run инструментом, правка курса это `Workflow({scriptPath, resumeFromRunId})` с новыми `args`.
- Ночные прогоны агента рутин идут через launchd и Codenv, хуки Claude Code там не действуют.

## Установка в другой репозиторий

```sh
bash scripts/окружение/harness-kit/install.sh /путь/к/репозиторию --dry-run   # показать, что будет сделано
bash scripts/окружение/harness-kit/install.sh /путь/к/репозиторию             # установить
bash scripts/окружение/harness-kit/install.sh /путь/к/репозиторию --no-gate   # без verify-gate и track-read, если state-файлов нет
```

Повторный запуск обновляет блоки между маркерами `harness-kit:start` и `harness-kit:end` и не дублирует хуки. Версия в `VERSION`.

## Что не вошло и почему

Kill-switch по умолчанию выключен в job_alloben (ночных прогонов без присмотра здесь нет); включается флагом там, где они есть, commit-on-stop (возражение Astra, Codex не покрыт), state-файл для каждой активности (где шаги делают люди, он вырождается в чекбоксы), `/goal` как гейт качества документов (оценщик не читает файлы).
