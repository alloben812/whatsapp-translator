---

Правило Anthropic: после каждого релиза модели убирать компоненты харнеса по одному и смотреть, что ещё держит результат. У нас носители правил только растут. Эта процедура делает обратное движение штатным. Период: `$ARGUMENTS` (например «с 2026-08-01»; по умолчанию последний квартал).

1. **Инвентарь носителей.** Размеры и число: `wc -l CLAUDE.md AGENTS.md`, число файлов в `.claude/commands/`, `.agents/skills/`, `.claude/agents/`, хуков в `.claude/settings.json` и `.codex/hooks.json`. Запиши таблицу «носитель · строк · файлов · дата последней правки».
2. **Противоречия и устаревшие указатели.** Запусти `python3 scripts/lint/lint.py` (если линт есть) и возьми проверки `claude_md_pointers` и `handoff_stacks`. Вручную: правила, которые описывают одно и то же в двух местах; пути в CLAUDE.md, ведущие в отсутствующие или исторические файлы; стартовые промпты, чей заголовок противоречит правилам CLAUDE.md.
3. **Что не использовалось.** Для каждого раздела CLAUDE.md и каждого скилла: есть ли след применения за период (упоминание в днях, HANDOFF, log.md, git log). Нет следа: кандидат на удаление или перенос в историю.
4. **Что перестало быть несущим.** Для правил, введённых против конкретной слабости модели (ресеты контекста, многословные напоминания, дубли «не выдумывай»): проверь, воспроизводится ли слабость на текущей модели в трёх недавних окнах. Не воспроизводится: предложить убрать.
5. **Стоимость прогонов за период.** Собери из HANDOFF строки «Прогоны»: сколько прогонов, токены, минуты, сколько остановлено по квоте или убито. Сравни с правилом «соло сначала».
6. **Отчёт.** `scripts/окружение/harness-kit/ревизии/ГГГГ-ММ-ДД.md`: таблица носителей, список «убрать / слить / оставить» с причинами, предложение по целевому размеру CLAUDE.md. Ничего не удаляй сам: удаление по явному ОК владельца, одним PR.
